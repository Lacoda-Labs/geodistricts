## 2127

## 2154
- after step 3, then detecting isolated tracts (2 found), click move isolated and tracts are moved.
then run step 4 and isolated tracts are back as if the step is not updated after move. indeed, clicking detect isolated tracts finds the same two tracts that were moved in step 3.

**FIXED:**
1. **Cache persistence issue**: When isolated tracts (or bridge tracts) were moved in step 3, the changes were only applied to the frontend's `currentStep.districtGroups`, but not persisted to the backend algorithm state or cached step. When step 4 was requested, it used the cached step 3 (without the moves) to calculate step 4, causing the moved tracts to reappear.

2. **Update algorithm state and invalidate cache**: Fixed by:
   - Updating frontend to send `state`, `step`, and `maxIterations` when calling `moveIsolatedTractsToOppositeGroup()` and `moveBridgeTractsAndRecheck()`
   - Updating backend endpoints to:
     - Update `algorithmState.currentGroups` with the moved groups
     - Update the step in `algorithmState.steps` array if it exists
     - Invalidate the cached step for the current step number
     - Invalidate all subsequent step caches (since they depend on the current step)
   
   This ensures that when step 4 is calculated, it uses the updated step 3 (with the moves), not the original cached step 3.

## 2046
- just reran the steps for AZ. problem remains as I have described. multiple move isolated clicks are required to move final isolated tracts. see logs.

**FIXED:**
1. **Observables created upfront with stale data**: The frontend was creating all observables upfront with the initial isolated tract IDs from `isolatedTractsByGroup`. After each move, the backend returns updated isolation data, but the subsequent observables were still using the initial isolated tract IDs, causing them to process stale data.

2. **Recursive processing with dynamic isolation state**: Changed `moveIsolatedTracts()` to use a recursive approach (`processNextGroup()`) that:
   - Processes groups one at a time sequentially
   - After each move, updates `this.isolatedTractsData` with the latest isolation result from the backend
   - After processing all initial groups, re-detects isolation to check if new isolation was created
   - If new isolation is found, processes those groups recursively
   - Continues until no more isolated tracts remain
   
   This ensures that each move uses the current isolation state, not the initial state, and automatically handles new isolation that may be created after each move. Now a single click will process all isolated tracts, including any new isolation created during the process, until all isolation is resolved.
