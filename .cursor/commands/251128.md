**Answers to caching questions:**
1. **What is being cached on browser?**
   - `showTractBoundaries`: Boolean preference for showing/hiding tract boundaries on the map
   - `selectedState`: The currently selected state code (e.g., "AZ", "CA")
   - These are stored in browser `localStorage` (per client/browser)

2. **Is cache per state stored in browser (by client)?**
   - No, the cache is NOT per state. It's just two simple values:
     - `showTractBoundaries`: A single boolean for the entire app (not per state)
     - `selectedState`: A single state code (only one state at a time, not multiple states)
   - These are stored in localStorage, which is per browser/client, but they're not per-state caches
   - **Backend caching**: Algorithm results and census data ARE cached per state on the backend (Firestore/Cloud Storage), but this is server-side, not browser-side

3. **Why does browser need to cache?**
   - The browser caches these for user convenience:
     - `showTractBoundaries`: So the user's UI preference persists across sessions
     - `selectedState`: So when the user navigates away and comes back, their last selected state is remembered
   - However, on production (geodistricts.org), we want `showTractBoundaries` to default to false for consistency, which has been fixed

4. **When host is geodistricts.org (i.e. gcp) no census tract data should be returned as default, i.e. Tract checkbox should be unchecked by default.**
   - ✅ FIXED: We now detect when hostname is `geodistricts.org` and default `showTractBoundaries` to `false` (unchecked)
   - Any cached value is cleared on production to ensure consistent default behavior

- union tracts for each district group (DG) are failing to be created and returned. add logging to debug if needed? if a DG has isolated tracts, the DG should return a list of union polygons.

## 1402
- AZ step 4, detect bridge tracts appears to fail as the map does not change border on "District 5
Component: 1 of 2" which should be identified as a bridge tract.

### Fix Applied ✅
- **Problem**: Bridge tract detection was failing for small isolations (like District 5 with 2 isolated tracts)
  - The filtering logic for small isolations was too restrictive: it required bridge tracts to NOT be in the main component AND NOT have all neighbors in the source group
  - This filtered out valid bridge tracts that were in the main component of the sibling group, even if they were adjacent to isolated tracts
  - Result: Bridge tracts that should connect isolated components were not being detected
  
- **Solution**:
  - Adjusted filtering logic for small isolations to be less restrictive:
    - Include if: (adjacent to >= 1 isolated tract AND not fully embedded) OR (adjacent to >= 2 isolated tracts)
    - This means even if a bridge tract is in the main component, if it's adjacent to 2+ isolated tracts, it will be included
  - Added comprehensive debug logging for all groups with isolated tracts (not just large ones)
  - Added specific debug logging for District 5 to help diagnose issues
  - Debug logging now shows why each candidate bridge tract is included or filtered out
  
- **Result**: Bridge tracts are now properly detected for small isolations, including District 5, allowing the map to correctly highlight bridge tracts that can connect isolated components

## Frontend Error Fix
- **Problem**: `TypeError: Cannot read properties of null (reading 'finalDistricts')` when algorithm completes immediately (0 iterations)
  - When the algorithm completes at step 0 (no iterations needed), the backend returns `step: null` with `isComplete: true`
  - Frontend code tried to access `newStep.finalDistricts` without checking if `newStep` was null
  - Result: Application crashed with null reference error
  
- **Solution**:
  - Added null check for `newStep` before accessing its properties
  - When algorithm completes and `newStep` is null, gracefully handle by:
    - Logging completion message
    - Using current step if available (algorithm was already complete)
    - Returning early to prevent null reference errors
  - Added additional null checks throughout the step processing logic
  
- **Result**: Application no longer crashes when algorithm completes immediately, gracefully handles completion state
