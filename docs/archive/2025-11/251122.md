## Isolation Logic Explanation

### Overview
The `fixIsolatedTractsAcrossAllGroups` function runs after each division step to ensure all tracts in each district group are connected. It uses an iterative approach that continues until no more isolation issues are found.

### Step-by-Step Process

#### 1. **Initial Setup** (Lines 1080-1100)
- Builds an adjacency graph for all tracts
- Creates a copy of district groups to modify
- Initializes tracking variables

#### 2. **Pre-Processing: Enclosed Tracts & Tract Groups** (Lines 1194-1305)
- Ensures enclosed tracts stay with their enclosing tracts
- Moves split tract groups back together
- Handles `ENCLOSED_BY` relationships

#### 3. **Main Iteration Loop** (Lines 1328-1789)
Runs up to 10 iterations until no isolation issues remain:

**For each district group:**
- Calculates max reachable count (main component size) using `calculateMaxReachableCount()`
- If `maxReachableCount < totalTractsInGroup`, isolation is detected

**Isolation Detection:**
- Finds the main component by locating the tract with the highest reachable count
- Performs BFS from that tract to find all reachable tracts
- Any tract not reachable is considered isolated

#### 4. **Fixing Isolation - Two Strategies**

**Strategy A: Move Bridge Tract** (Lines 1477-1636)
- Finds a tract in another group that is adjacent to isolated tracts
- Selects the tract adjacent to the most isolated tracts
- Before moving, checks:
  1. Is it in the main component of its current group? (≥95% of max reachable)
  2. Are all its neighbors in the source group? (fully embedded)
  3. Would it be isolated in the target group? (no neighbors in target)
- If any check fails, skip moving that tract
- If moved:
  - Moves the bridge tract to the isolated group
  - Balances population by moving adjacent tracts back to preserve division ratio

**Strategy B: Move Isolated Tracts** (Lines 1637-1781)
- Used when no suitable bridge tract is found
- Finds the best target group (one with the most adjacent neighbors to isolated tracts)
- Moves isolated tracts to that group
- If isolated tracts are in a tract group, moves all group members together
- Balances population by moving adjacent tracts back

#### 5. **Population Balancing** (Lines 1610-1635, 1720-1741)
- After moving tracts, finds adjacent tracts in the receiving group
- Moves them back to the giving group to preserve population division ratio
- Stops when population is approximately balanced

#### 6. **Final Verification** (Lines 1795-1817)
- Re-checks all groups after fixes
- Logs any remaining isolation issues
- Reports total tracts moved and time taken

### Helper Functions

**`calculateReachableTracts(tractId, groupTracts, adjacencyGraph)`**
- Uses BFS to count how many tracts are reachable from a given tract within a group
- Returns the size of the connected component containing that tract

**`calculateMaxReachableCount(groupTracts, adjacencyGraph)`**
- Calculates reachable count for every tract in the group
- Returns the maximum (the main component size)

### Safeguards

1. Iteration limit: max 10 iterations to prevent infinite loops
2. Bridge tract validation: prevents moving tracts that would become isolated or are critical to their current group
3. Tract group preservation: keeps enclosed/enclosing tracts together
4. Population balancing: maintains division ratios when moving tracts

### Design decisions

- Uses max reachable count (main component) instead of checking from the first tract, which is more robust
- Iterative approach: re-checks all groups after each fix since fixing one group can create issues in others
- Prefers moving bridge tracts over isolated tracts when possible, as it's less disruptive

This should catch and fix isolation issues that arise during the division process.
